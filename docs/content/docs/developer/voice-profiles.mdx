## Data and ownership

Profiles are managed by `backend/services/profiles.py` through
`backend/routes/profiles.py`. ORM models live in `backend/database/models.py`.

- `voicebox.db` stores names, language, description, personality, voice type,
  engine/preset choices, effects, and sample transcripts.
- `profiles/{profile_id}/` stores processed sample WAVs and optional avatars.
- Exact-generation snapshots retain immutable reference content separately.
- Model weights are in the Hugging Face cache, not inside each profile folder.

A cloned profile uses reference audio/transcripts. A preset profile uses an
engine/voice identifier and needs no sample. Presets are bound to their engine;
profile/engine compatibility is checked before inference.

## Create and add samples

`POST /profiles` creates metadata. `POST /profiles/{id}/samples` accepts multipart
`file` and required `reference_text`. A sample is bounded to 30 seconds and 50 MiB;
the exact transcript is 1–1,000 characters. Supported upload extensions are
checked before bounded spooling and decoding. Saving a sample converts it to
the backend's supported reference representation.

The frontend may request transcription to help fill the text, but the sample
endpoint requires a confirmed transcript. It does not invent one automatically.
Missing or incompatible cloning references fail rather than becoming a generic voice.

## Conditioning and exact identity

Engines create/combine their own prompt representations; the shared profile
service manages reference selection and cache identity. Stable voice binding
uses reference content, text, and relevant metadata rather than assuming a
database UUID proves the same acoustic input.

Exact snapshots retain validated copies for pinned requests. Profile mutations,
deletion, generation, and snapshot reuse must retain their ownership/cancellation
contracts. Use existing service methods rather than editing the database or
reference files behind them.

## Import and export

`GET /profiles/{id}/export` creates a ZIP with supported profile metadata,
sample audio/transcripts, and optional avatar. Cloned exports contain reference
audio, not just embeddings. Preset exports retain engine/voice metadata and need
that engine available when subsequently generating.

`POST /profiles/import` validates archive paths, sizes, metadata, and audio before
publishing a new profile. It restores supported personality, engine/type/preset,
effects, samples, and avatar metadata. It does not update an existing profile by
name; imports can receive a disambiguated name. The private narrator import tool
has a separate idempotent update workflow.

## UI and security

Voices are edited under `app/src/components/VoicesTab/` and `VoiceProfiles/`.
`ServerImage` fetches avatars with the current server's bearer headers, bounds
the download, and releases old object URLs after a connection change.
Profile deletion may be rejected when active generation or story ownership
would be broken. The API response gives the reason.
