---
title: "Audio Channels"
description: "Backend channel assignments and platform-owned playback routing"
---

Audio channels associate voice profiles with output devices. A channel can have
multiple devices, and a profile can use multiple channels. This supports, for
example, sending a narrator to both headphones and a virtual streaming device.

## Ownership and storage

Channel metadata and mappings live in the connected backend's SQLite database:
`AudioChannel`, `ChannelDeviceMapping`, and `ProfileChannelMapping` in
`backend/database/models.py`. The default channel is seeded at database startup
and cannot be renamed, reassigned through channel update, or deleted.

Device IDs come from the client operating system. Storing an ID on a remote
backend does not make that device available on another computer. Recheck mappings
after changing devices or switching client platforms.

## Request and playback flow

1. The client enumerates output devices through its platform adapter.
2. Settings stores channel names, device IDs, and voice assignments through REST.
3. Playback resolves the profile's configured channels and opens the selected
   client devices.

The backend stores routing configuration; it does not play through a remote
client's speakers. Shared React code uses the platform contract, while desktop
audio operations live in the Tauri adapter and Rust implementation. Native output
reports readiness and errors explicitly; a routing failure does not silently
send private audio to a different speaker.

## API

| Method | Path | Purpose |
| --- | --- | --- |
| GET / POST | `/channels` | List or create channels |
| GET / PUT / DELETE | `/channels/{channel_id}` | Read, update, or delete a channel |
| GET / PUT | `/channels/{channel_id}/voices` | Read or replace voice assignments |
| GET / PUT | `/profiles/{profile_id}/channels` | Read or replace channel assignments |

For example, channel creation accepts:

```json
{
  "name": "Monitor",
  "device_ids": ["DEVICE_ID_FROM_THIS_CLIENT"]
}
```

Assign profiles with `{"profile_ids":["PROFILE_ID"]}` or assign channels with
`{"channel_ids":["CHANNEL_ID"]}` on the corresponding PUT route. Use the
[API reference](/api-reference) for complete schemas and remote authentication.

## Code map and validation

| Path | Responsibility |
| --- | --- |
| `backend/routes/channels.py` | HTTP endpoints and error responses |
| `backend/services/channels.py` | Channel and assignment persistence |
| `backend/database/seed.py` | Initial default channel |
| `app/src/platform/` | Shared audio contract |
| `tauri/src/platform/` | Desktop adapter |
| `tauri/src-tauri/src/` | Native output devices and streams |
| `web/src/` | Browser platform implementation |

Validate routing changes with shared tests and native tests, then check real
devices. Browser audio permissions, supported output APIs, and native device IDs
are platform-specific. See [architecture](/developer/architecture) for the broader
ownership boundaries.
