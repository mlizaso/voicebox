## Engine registry

`backend/backends/__init__.py` defines engine protocols, `ModelConfig` metadata,
factories, and model-size resolution. Registered engines are Qwen, Qwen
CustomVoice, LuxTTS, Chatterbox Multilingual, Chatterbox Turbo, TADA, and Kokoro.
Qwen cloning supports 0.6B/1.7B; TADA supports 1B/3B. Unsupported combinations are
rejected before queueing. Single-variant engines ignore irrelevant legacy sizes.

Platform detection chooses the available implementation. Qwen uses MLX on
supported Apple Silicon and PyTorch elsewhere; other engines have their own
runtime/device support. MLX uses Metal, not an asserted Neural Engine speedup.
See [adding an engine](/developer/tts-engines) for the complete integration path.

## Durable generation

1. `routes/generations.py` validates the profile, engine/model, request, and any
   required implementation revision.
2. The accepted request is persisted and admitted to the generation queue.
3. `services/generation.py` obtains the profile conditioning and invokes the
   engine through the existing lifecycle guard.
4. `utils/chunked_tts.py` performs the normal chunk plan and crossfade.
5. Normalization/effects follow accepted settings, then audio/version/history
   publication completes with durable ownership and recovery handling.

The queue serializes durable generation. MLX model load/use/unload and migration
share lifecycle coordination; cancelling a caller must not free a model while
its blocking inference is still running.

## Settings and replay

`GenerationRequest` accepts 1–50,000 characters, 100–5,000-character chunk limits
(default 800), 0–500 ms crossfade (default 50), optional unsigned 32-bit seed,
and normalization (default true). Engine/language support is also validated.
Personality rewriting changes text before synthesis when requested.

The database stores chunk size, crossfade, and `normalize_audio` for new rows.
Retry reuses these settings and the seed. Regenerate produces a new take while
retaining accepted settings. Legacy NULL fields preserve previous replay defaults.
Direct imports have no synthesis request and return a conflict on replay.

Do not introduce a second copy of generation/history fields: `HistoryResponse`
inherits `GenerationResponse`. Portable generation archives retain these settings
and the selected audio bytes.

## Streaming and exact callers

`POST /generate/stream` exposes supported streaming backends. Exact routes are
`/generate/exact`, `/generate/batch/exact`, and `/generate/stream/exact`.
They bind normalized input, frozen reference content, and a known implementation
revision; incompatibility fails before untrusted output can be adopted.

`backends/mlx_runtime.py` owns the pinned implementation identity. The local
source fingerprint also covers executable request/schema code, so a validation
change may require a fingerprint refresh. Never weaken this guard merely to
resume an old job after an upgrade. Test that the computed and embedded identity
agree, and keep the saved job's runtime compatible.

## Performance without changing output

Reuse the loaded model and verified conditioning/chunk caches; avoid concurrent
workers competing for the same Apple GPU. The existing MLX Qwen path includes
the guarded speaker-embedding dtype correction and reference-prefix vocoding
optimization. Exact tests must cover any future change to those paths.

The optional private renderer also avoids unnecessary FFmpeg PCM reads and
checkpoint serialization overhead. It is a separate ignored workspace; those
optimizations do not change the studio's model settings. A passing unit suite
does not establish full-book listening equivalence or wall-clock throughput.
Benchmark representative fixed inputs before changing precision, samples,
chunking, sampling, or mastering.
