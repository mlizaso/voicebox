## System overview

The shared React studio runs in a browser (`web/`) or Tauri desktop (`tauri/`).
Both use a FastAPI backend with SQLite and pluggable TTS/STT/LLM implementations.
HTTP carries API and media requests; event streams carry progress. Packaged
desktop builds launch a PyInstaller sidecar, while development normally starts
the Python module explicitly.

```text
app/src/ shared UI
  -> app/src/lib/api/ handwritten authenticated client
  -> backend/routes/ validation and coordination
  -> backend/services/ queue, business operations, publication
  -> backend/backends/ model inference
  -> backend/database/ and managed data files
```

## Frontend ownership

| Path | Role |
| --- | --- |
| `app/src/AppRoot.tsx`, `app/src/App.tsx` | Shared composition and screens |
| `components/VoicesTab`, `VoiceProfiles` | Voice browser, inspector, profile/sample editing |
| `components/Generation`, `History` | Generation form and durable history |
| `components/StoriesTab`, `CapturesTab` | Clip composition and recordings/transcripts |
| `components/ServerTab`, `ServerSettings` | Connection, generation/capture, model/GPU settings |
| `lib/api/` | Client, schemas, bounded downloads, bearer authentication |
| `lib/hooks/`, `stores/` | Queries, media lifecycle, settings and connection state |
| `platform/` | Shared interface for platform operations |
| `web/src/platform/`, `tauri/src/platform/` | Browser/native implementations |

Shared code must not import Tauri APIs directly. A connection identity isolates
queries, recording results, avatars, audio, and the dictation window from a server
switch. The shared `ServerImage` handles authenticated avatars and object-URL
cleanup. Tokens remain in memory; media fetches omit cookies.

## Backend ownership

| Path under `backend/` | Role |
| --- | --- |
| `main.py`, `server.py` | Python module / frozen sidecar entry points |
| `app.py` | Middleware, routers, startup/shutdown |
| `api_security.py`, `request_limits.py` | Peer/Host/origin/bearer checks and bounded admission |
| `config.py`, `data_permissions.py` | Data roots and private managed files |
| `models.py` | Pydantic API models; history extends the generation response |
| `routes/generations.py` | Request validation, exact contracts, queue admission/replay |
| `services/generation.py`, `task_queue.py` | Generation modes, serialized execution, output publication |
| `services/profiles.py`, `history.py` | Voice identity, metadata and history ownership |
| `services/export_import.py`, `deletion_journal.py` | Portable archives and durable filesystem recovery |
| `backends/__init__.py` | Engine protocols, model registry, model-size resolution |
| `backends/mlx_tts_lifecycle.py`, `mlx_runtime.py` | MLX lifecycle and pinned implementation identity |
| `database/` | Models, sessions and additive startup migrations |
| `utils/` | Chunking, audio/effects, cache, progress and upload helpers |
| `mcp_server/`, `mcp_shim/` | MCP tools and bounded stdio transport |

Routes validate and delegate, but exact-generation coordination remains in the
route layer. Adding an engine also requires API schemas, frontend choices, and
packaging validation; a registry entry alone is not a complete integration.

## Generation and storage

Durable requests record accepted parameters, enter a serial queue, create voice
conditioning, invoke an engine, and publish audio/history versions. New records
persist chunking, crossfade, and normalization for replay; old rows retain legacy
defaults. Publication, cancellation, and deletion keep file ownership aligned
with durable database state.

Exact callers additionally bind normalized requests, reference snapshots, and
implementation revision. A source/runtime change can invalidate an old exact
resume even when it changes validation rather than waveform math. Never bypass
that check to reuse incompatible chunks.

SQLite stores metadata/transcripts, while profiles, generations, captures, and
snapshots are managed files. Model weights use the Hugging Face cache separately.
See [storage](/overview/storage-and-backup) and [TTS generation](/developer/tts-generation).

## Native boundary

Rust owns the sidecar lifecycle, global capture/hotkeys, clipboard/focus targets,
audio output, and directory opening. An occupied server port is not proof of
ownership; reuse requires an explicit connection action. Native folder opening
requires the current loopback Voicebox connection and rejects network/device paths
before filesystem access. Browser clients use the web adapter's supported fallbacks.

## Other applications and records

`landing/` is the public site; `docs/` is a separate Fumadocs workspace. The ignored
private `voice-profile/build/` renderer is its own local repository and talks to
the backend over the exact API. Design proposals and old benchmarks remain in
`docs/plans/` and `RUN_NOTES.md`; they describe their stated revisions, not the
current startup contract.
