## Overview

Remote Mode allows you to run the Voicebox backend on a separate machine (like a GPU server) while using the desktop app on your local machine.

## Use Cases

- **No local GPU** - Use a cloud GPU or remote workstation
- **Faster generation** - Leverage powerful remote hardware
- **Shared infrastructure** - Multiple users connect to one server
- **Laptop workflows** - Keep your laptop cool and battery-efficient

## Architecture

In Remote Mode, the Voicebox desktop app (running on your local machine) communicates with the backend server (running on a remote machine) over HTTPS or a loopback tunnel. The local app provides only the user interface, while the remote server handles all the heavy processing including the TTS models, API endpoints, and audio generation.

## Setting Up Remote Mode

### On the Server

<Steps>
  <Step title="Install Dependencies">
    ```bash
    # Clone the repo
    git clone https://github.com/jamiepine/voicebox.git
    cd voicebox/backend

    # Install Python dependencies
    pip install -r requirements.txt

    # Engines with incompatible transitive pins — install with --no-deps
    pip install --no-deps chatterbox-tts
    pip install --no-deps hume-tada

    # Qwen3-TTS from source
    pip install git+https://github.com/QwenLM/Qwen3-TTS.git
    ```

    Or just run `just setup` from the repo root, which handles all of this.
  </Step>

  <Step title="Start the Server Behind TLS">
    ```bash
    # Generate this once and store it in your secret manager.
    export VOICEBOX_REMOTE_API_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(32))')"

    # Keep the public request authority explicit.
    export VOICEBOX_TRUSTED_HOSTS="voicebox.example"

    # Bind Voicebox to loopback, then publish it through your TLS reverse proxy.
    uvicorn backend.main:app --host 127.0.0.1 --port 17493
    ```

    <Callout type="warn">
      A bearer token authenticates a client but does not encrypt traffic.
      Voicebox rejects remote API authentication over plain HTTP by default.
      Configure the proxy to pass the public Host and HTTPS scheme, and trust
      proxy headers only from the proxy itself.
    </Callout>
  </Step>

  <Step title="Open Only the TLS Listener">
    ```bash
    # Example for an HTTPS reverse proxy on Ubuntu/Debian
    sudo ufw allow 443/tcp

    # Or use your cloud provider's firewall settings
    ```

    Keep Voicebox's loopback port `17493` closed to the network. The reverse
    proxy is the only public listener.
  </Step>
</Steps>

### On the Client

<Steps>
  <Step title="Open Settings">
    In Voicebox, go to **Settings → Server**
  </Step>

  <Step title="Enable Remote Mode">
    Toggle **Use Remote Server**
  </Step>

  <Step title="Enter Server URL">
    ```
    https://voicebox.example
    ```

    Replace the example with the HTTPS authority configured in
    `VOICEBOX_TRUSTED_HOSTS`.
  </Step>

  <Step title="Enter the API Token">
    Paste the same `VOICEBOX_REMOTE_API_TOKEN` value into **Settings → Server →
    Remote API token**. Voicebox sends it only to the configured server origin.
  </Step>

  <Step title="Test Connection">
    Click **Test Connection** to verify
  </Step>
</Steps>

## Security Considerations

<Callout type="warn">
  Never treat a bearer token sent over plain HTTP as secure. Anyone able to
  observe the connection can replay it. Keep the token out of URLs and logs.
</Callout>

**Best Practices:**
- Prefer HTTPS, or an SSH loopback tunnel when only one client needs access
- Keep the built-in bearer token enabled even behind a reverse proxy
- Run behind an additional reverse-proxy authentication layer when appropriate
- Firewall rules to limit access to specific IPs

### Loopback tunnel alternative

Keep Voicebox bound to `127.0.0.1` on the server and forward it with SSH:

```bash
ssh -N -L 17493:127.0.0.1:17493 user@voicebox.example
```

The client can then use `http://127.0.0.1:17493`; the bearer never crosses a
plaintext network hop.

### Explicit insecure compatibility mode

Direct `--host 0.0.0.0` is plain HTTP. It remains available for specialized
deployments only after the operator explicitly sets
`VOICEBOX_ALLOW_INSECURE_REMOTE_HTTP=1`. This override permits replayable
credentials and is not a substitute for TLS. The Voicebox browser/desktop
client still refuses non-loopback `http://` server URLs, so use it only with a
separately secured transport and a client whose risk you have evaluated.

## Performance

Expected performance on various GPUs:

| GPU | Generation Speed |
|-----|------------------|
| RTX 4090 | ~2-3s per 10 words |
| RTX 3090 | ~3-4s per 10 words |
| RTX 3060 | ~5-7s per 10 words |
| CPU (12-core) | ~20-30s per 10 words |

<Callout type="info">
  A GPU with 8GB+ VRAM is recommended for best performance.
</Callout>
