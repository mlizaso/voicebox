## What runs where

The client displays the studio; the remote backend stores profiles/captures/history,
loads models, and generates audio. Model/GPU capacity and all server-side paths
belong to that machine. This API is not a multi-tenant account-isolation system:
clients sharing its token access the same server data.

Remote hardware may improve throughput, but compare the same model, references,
sampling, and processing before treating it as a quality-preserving migration.

## Server setup

Set up this checkout with `just setup-python`. Keep the API on loopback behind an
HTTPS reverse proxy. Generate a persistent token once and retain it securely:

```bash
export VOICEBOX_REMOTE_API_TOKEN="$(python3 -c 'import secrets; print(secrets.token_urlsafe(32))')"
export VOICEBOX_TRUSTED_HOSTS="voicebox.example"
backend/venv/bin/python -m backend.main \
  --host 127.0.0.1 --port 17493 --data-dir /absolute/path/to/voicebox-data
```

Publish the proxy's TLS listener, not the backend port. Preserve the public Host
and HTTPS request scheme; trust forwarded headers only from the proxy. If a web
UI uses another origin, add its complete origin to `VOICEBOX_CORS_ORIGINS`.
Both settings require explicit values; wildcard hosts/origins are refused.

```bash
curl --fail -H "Authorization: Bearer $VOICEBOX_REMOTE_API_TOKEN" \
  https://voicebox.example/health
```

The token is 32–512 URL-safe ASCII characters. A token authenticates requests;
HTTPS protects it in transit. Do not put it in URLs, logs, screenshots, or commits.

## Client setup

Open **Settings → Server**, choose the remote server connection, enter the HTTPS
URL and **Remote API token**, and test/connect. The app sends bearer headers to
that server origin for API calls, avatars, audio, and event streams. It omits
cookies and keeps credentials in memory; a restart may require entering them again.

Switching connections clears the previous server's cache and cancels/discards
stale media or recording results. The native dictation window mirrors the active
connection in memory. Local folder-opening controls are disabled for remote servers.

## Loopback SSH tunnel

For a private connection, keep the backend bound to loopback and forward it:

```bash
ssh -N -L 17493:127.0.0.1:17493 user@voicebox.example
```

Connect to `http://127.0.0.1:17493`. The actual network hop is protected by SSH.
The backend sees a direct local request; this grants the local API's privileges,
including MCP server-local path access. Use it only for a server you control.
Paths still belong to the remote filesystem, even though the URL is loopback;
do not use local folder buttons to interpret them.

## Compatibility and limits

Requests can omit authentication only if both their peer and Host are local.
An HTTPS reverse proxy with a public Host still requires a bearer token. Server-local
MCP transcription paths are denied to remote calls even when authenticated;
upload base64 audio instead.

Non-loopback plain HTTP is rejected by the app. The server's explicit
`VOICEBOX_ALLOW_INSECURE_REMOTE_HTTP=1` compatibility option permits unencrypted
transport and is not a public deployment recipe. The supplied Compose file uses
it only for its private bridge behind a host-loopback listener; see [Docker](/overview/docker).

For missing profiles, inspect the connected server's `/health/filesystem` rather
than the client machine's app directory. See [storage](/overview/storage-and-backup)
and [troubleshooting](/overview/troubleshooting).
