## Start with the actual backend

Many apparent missing-profile or slow-generation problems come from connecting to
a different backend. Ordinary development uses **17493**; this machine's private
audiobook launcher uses **17494**. A packaged app normally has its own data root.

```bash
curl --fail --silent --show-error http://127.0.0.1:17493/health \
  | python3 -m json.tool

curl --fail --silent --show-error http://127.0.0.1:17493/health/filesystem \
  | python3 -m json.tool
```

Replace the port for the server you intend to inspect. Remote requests require
the configured bearer token. Compare the URL, runtime/device, revision, and data
paths before changing settings or reinstalling anything.

## Server startup and connection

| Symptom | Action |
| --- | --- |
| Backend environment missing | Run `just setup-python` from the repository root. |
| Wrong port | Pass `--port 17493` explicitly; `python -m backend.main` alone defaults to 8000. |
| Desktop finds an occupied port | Use **Connect to my running server** only for a server you started. |
| Generation stops after source edits | Run the stable backend without `--reload`; resume durable work. |
| Data-root ownership/lock error | Stop the other backend using that root, then start one owner. |
| Remote URL rejected | Check HTTPS, token, trusted hosts, and browser origin settings. |

Stable launch from the repository root:

```bash
backend/venv/bin/python -m backend.main \
  --host 127.0.0.1 --port 17493 --data-dir /absolute/path/to/data
```

Use an existing or intentionally new absolute data directory. On Windows the
interpreter is `backend\venv\Scripts\python.exe`. See
[quick start](/overview/quick-start) and [remote mode](/overview/remote-mode).

## Profiles and database

A profile requires database metadata plus reference WAVs. If profiles or history
appear missing, inspect `/health/filesystem` and your selected server. Copying
only `profiles/` does not restore names and transcripts stored in `voicebox.db`.

For database locks, stop conflicting processes and preserve the data root before
repairing or restoring it. **Do not delete SQLite WAL/SHM files as a repair step**;
they may contain committed data. Back up the whole root while stopped, or use
profile/generation ZIP exports. See [storage and backup](/overview/storage-and-backup).

Current profile ZIP imports retain supported metadata present in the archive and
create a new uniquely named profile. Re-importing is not an update operation;
older bundles may lack fields added since they were created.

## Slow generation and quality

The first request may download and load weights. Separate that from steady-state
synthesis. Check [GPU acceleration](/overview/gpu-acceleration): some engines
deliberately use CPU on macOS even when health detects a GPU.

Use one model worker for the private audiobook pipeline and avoid competing
renders. Keep text, reference audio, model, seed, chunking, and mastering fixed
when comparing performance. Model-size or precision changes need a separate
quality evaluation. An optional-library warning alone is not evidence that
replacing the pinned dependency stack will help.

For poor voice matches, check clean reference audio, an exact transcript,
language/engine compatibility, and the selected profile. Compare a short sample
before changing a whole book. Personality rewriting changes words; disable it
when text must be narrated exactly.

## Memory, disk, and recovery

| Symptom | Action |
| --- | --- |
| Out of memory | Unload unused models and stop competing workloads; inspect the engine's device log. |
| HTTP 413 | Check upload bytes, decoded duration, and endpoint limits. |
| HTTP 429 | Wait for the active operation or admission slot to finish. |
| HTTP 507 | Check free space on backend data, temporary, model-cache, and output volumes. |
| Exact-runtime mismatch | Restore the matching implementation or create a new job; retain saved progress/audio. |
| Interrupted book | Reopen the private wizard and choose **Resume**; do not edit saved hashes. |

Private audiobook recovery is documented in the repository's `docs/AUDIOBOOKS.md`.
Successful output playback does not prove the work directories can be deleted
while an unfinished job still needs them.

## Playback, recording, and dictation

Check the selected microphone/output device, OS permissions, and channel mappings.
Native routing failures are surfaced instead of silently switching speakers.
Global hotkeys and auto-paste require the desktop implementation; the browser
does not provide the same native controls.

Enable dictation and complete its readiness checks in **Settings → Captures**.
If paste is skipped or the target cannot be validated, copy the saved transcript
from Captures. A failed paste does not justify sending text to an arbitrary
focused window. See [dictation](/overview/dictation).

Remote audio and avatars require the same authenticated connection as ordinary
API calls. Re-enter an in-memory token after restarting the client if necessary.
Folder controls remain local-desktop-only.

## Builds and updates

Use [development setup](/developer/setup) and [building](/developer/building) for
the correct Python, Bun, Rust, and native toolchain. On macOS, an `actool` failure
can mean Xcode is not selected. An MLX native-library failure in a frozen bundle
requires checking packaged resources, not merely a source-environment import.

Do not bypass invalid update signatures. Check the release manifest, key, and
artifact as described in [updating](/developer/autoupdater). This fork's updater
still points to upstream, so record the actual commit/build when reporting a fix
that seems absent.

## Collect useful diagnostics

Record the build/commit, operating system, selected engine/model, server URL/port,
sanitized health response, relevant log error, and a minimal reproduction. Omit
tokens, private voice samples, and book content. Include whether the issue occurs
in source development, a frozen desktop build, browser mode, or a remote backend.
