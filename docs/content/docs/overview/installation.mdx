## Choose the version you want to run

This documentation describes the `mlizaso/voicebox` checkout. To run its current
changes, follow [development setup](/developer/setup) or build its installer.
The landing site and configured desktop updater still point to
[upstream releases](https://github.com/jamiepine/voicebox/releases). Check a
release's actual assets for your operating system and processor; an upstream
installer does not necessarily include this fork's later changes.

## Run from source

Install Python 3.12+, Bun, and `just`. Desktop development also needs Rust and
the native platform tools. On macOS, use Xcode for desktop builds.

```bash
git clone https://github.com/mlizaso/voicebox.git
cd voicebox
just setup
just dev
```

For browser development, use `just dev-web` and open the Vite URL printed in the
terminal. Both development recipes start the backend on port **17493**. Use
[quick start](/overview/quick-start) for a stable backend without automatic
reload during long generations.

The setup recipe handles platform-specific model dependencies. It does not
download every model or install the private audiobook workspace.

## Use a packaged desktop app

Choose the package matching the release, OS, and processor. On macOS, install
the app in Applications; on Windows, run the supplied installer. The packaged
app normally starts its bundled backend. If a server already occupies its port,
connect explicitly only when it is a server you started.

Profiles and audio belong to the active backend. Packaged app data normally lives
at:

| Platform | Data root |
| --- | --- |
| macOS | `~/Library/Application Support/sh.voicebox.app/` |
| Windows | `%APPDATA%/sh.voicebox.app/` |
| Linux | `$XDG_DATA_HOME/sh.voicebox.app/`, normally `~/.local/share/sh.voicebox.app/` |

Source development from the repository root uses `./data/`. There is no extra
`data/` suffix in the packaged paths. See [storage and backup](/overview/storage-and-backup)
before moving data or diagnosing missing profiles.

## Models and hardware

The first request may download and load the selected engine. Weights are cached
separately from application data, normally under `~/.cache/huggingface/hub/`.
Use Settings to inspect installed models and disk space. Requirements vary by
engine, model size, and input length; budget space for weights and generated audio.

Apple Silicon can use the pinned MLX/Metal stack. Other engines and platforms
use their supported PyTorch CPU, CUDA, or ROCm path. A working desktop window
does not by itself prove the desired model accelerator is active: check `/health`
and perform a short generation. See [GPU acceleration](/overview/gpu-acceleration).

## Verify the installation

1. Confirm the backend status in the app, or open `http://127.0.0.1:17493/health`.
2. Open **Voices** and create a preset profile or a clone with reference audio.
3. Generate a short passage and play it back.
4. Check the selected server and its `/health/filesystem` paths before importing
   your existing profiles or starting a long job.

Continue with [quick start](/overview/quick-start), [remote mode](/overview/remote-mode),
or the [Docker guide](/overview/docker).
