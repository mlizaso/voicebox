A capture pairs a saved audio clip with its transcript and processing metadata.
Open **Captures** for recordings, dictations, and uploaded files. Capture data
belongs to the selected backend; a remote connection sends audio to that server.

## Create and find captures

Record with the in-app microphone, use supported desktop dictation, or upload a
file. Accepted capture extensions are `.wav`, `.mp3`, `.m4a`, `.flac`, `.ogg`, and
`.webm`, subject to upload and decoded-duration bounds. Capture uploads are limited
to 100 MiB and 30 minutes.

The list shows transcripts, source, and timestamps. Search filters the loaded
captures by raw or refined transcript. Select a row to replay its original audio
and switch between raw and refined text. The transcript display is read-only;
copy or export it to edit elsewhere.

## Transcription and refinement

**Settings → Captures** controls the transcription model, language, refinement,
dictation, and default playback voice. New settings default to Whisper **Turbo**
and automatic language detection. Existing saved settings remain authoritative.

Retranscription runs the saved audio through Whisper again. Refinement is a
separate operation using the local LLM, with controls for cleanup, self-corrections,
and technical terms. The client can chain it automatically after capture creation.
The raw transcript is retained when a refined version is saved.

Refinement can change wording; review it before copying into important content.
See [dictation](/overview/dictation#refinement) and
[transcription](/developer/transcription) for implementation details and model selectors.

## Playback and export

- Play the original recording from the capture player.
- **Play as** synthesizes the capture's text through a selected voice profile.
- Copy a transcript, export audio as WAV, export text, or export Markdown with
  metadata and available raw/refined transcripts.
- Delete captures you no longer need through the app.

To use captured audio as a cloning sample, export the WAV and upload a suitable
excerpt to a voice profile. Samples must fit the profile's 30-second limit and
include an exact reference transcript of at most 1,000 characters. The current
API has no special capture-to-profile promotion endpoint.

## Storage and connection scope

Audio lives beneath `<data-root>/captures/`; metadata and transcripts live in
`voicebox.db`. Keep both in a full backup. Folder-opening controls are available
only for a local desktop connection. See [storage and backup](/overview/storage-and-backup)
for the actual platform paths and the filesystem health endpoint.

## API surface

| Method | Path | Purpose |
| --- | --- | --- |
| POST | `/captures` | Multipart audio upload and transcription |
| GET | `/captures` | Paginated capture list |
| GET / DELETE | `/captures/{capture_id}` | Read or delete a capture |
| GET | `/captures/{capture_id}/audio` | Fetch original audio |
| POST | `/captures/{capture_id}/retranscribe` | Rerun transcription |
| POST | `/captures/{capture_id}/refine` | Refine the transcript |
| GET | `/capture/readiness` | Capture/dictation readiness |
| GET / PUT | `/settings/captures` | Saved defaults |

Creation fields are `file`, `source`, optional `stt_model`, and optional
`language`. The standalone `/transcribe` endpoint instead calls its model field
`model`. Use the [API reference](/api-reference) for complete request schemas,
limits, and bearer authentication.
