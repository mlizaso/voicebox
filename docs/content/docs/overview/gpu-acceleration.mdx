---
title: "GPU Acceleration"
description: "Check the actual engine device without changing generation quality"
---

Voicebox detects available runtimes, but each engine chooses only devices its
implementation supports. A GPU shown in Settings does not mean every engine uses
it. Check the model's load log as well as `/health` when investigating slow output.

## Apple Silicon

The platform selector uses MLX when it can import the native MLX runtime on arm64
macOS. Qwen cloning and Whisper then use their MLX implementations with **Metal
GPU acceleration**. If MLX cannot load, the general selector falls back to
PyTorch; exact audiobook generation separately requires its matching runtime.

Current device choices on macOS are:

| Engine | Implementation/device |
| --- | --- |
| Qwen cloning | MLX/Metal when available; otherwise the PyTorch path |
| Whisper | MLX when available; otherwise the PyTorch path |
| LuxTTS | PyTorch with MPS permitted |
| Chatterbox / Chatterbox Turbo | PyTorch CPU on macOS |
| TADA | PyTorch CPU on macOS |
| Kokoro | PyTorch with MPS disabled |
| Qwen CustomVoice | PyTorch with MPS disabled |

These choices are explicit in `backend/backends/` and
`backend/backends/base.py`. Do not force an unsupported device or upgrade the
pinned numerical stack to work around slow synthesis. The source setup recipe
installs the compatible Apple Silicon dependencies.

## Windows and Linux

PyTorch engines can use CUDA/HIP when the installed runtime reports it available.
Intel XPU and DirectML are enabled only by engines that opt into those paths,
and require their corresponding packages. Detection is not a guarantee that
every model or operation is supported.

For packaged Windows installations, Settings exposes separate **CUDA** and
**ROCm** backend downloads when supported. Their server core and GPU libraries
are packaged separately; matching libraries can be reused across updates.
Use the reported download sizes and status rather than assuming a fixed size.
See [backend updates](/developer/autoupdater).

Linux source and container installations need the appropriate PyTorch build,
driver/device access, and engine dependencies in the environment actually running
the backend. The repository's default Compose service is CPU; its ROCm overlay
is a separate configuration. Docker on macOS does not supply native MLX/Metal.

## Verify the running backend

```bash
curl --fail --silent --show-error http://127.0.0.1:17493/health \
  | python3 -m json.tool
```

For the private audiobook launcher, use port **17494**. Remote requests require
the configured bearer token. Inspect `backend_type`, `backend_variant`, GPU
information, compatibility warnings, and the TTS implementation revision. Then
check the selected engine's startup/model-load log and generate a short passage.

## Investigate slow generation

1. Separate first-time download and model loading from synthesis time.
2. Confirm the selected server, engine, model size, and actual device.
3. Keep the backend running without reload for long jobs and avoid concurrent
   model workers competing for the same GPU and memory.
4. Check memory and free space on the model, backend-data, and output volumes.
5. Compare the same text, reference, seed, and processing settings when measuring
   an optimization. A smaller model or different chunk size changes the contract.

Existing audiobook optimizations reuse verified phrases, avoid unnecessary
FFmpeg processes for compatible PCM reads, and reduce checkpoint serialization.
They do not require lowering quality. Full-book speed still depends on the
amount of new speech and the chosen device; no universal speed multiplier is
promised.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| Qwen runs on CPU on Apple Silicon | Use the backend environment prepared by `just setup-python`; inspect MLX import/load errors. |
| GPU appears in health but a model uses CPU | Check that engine's device policy in the table/source. |
| CUDA/ROCm installation fails | Review compatibility, download status, free space, and checksum errors before restarting. |
| Exact TTS revision mismatch | Restore the job's matching runtime or start a new job; retain existing progress and audio. |
| Out of memory | Unload unused models and stop competing workloads; do not silently change model or precision. |

For server placement and authentication, see [remote mode](/overview/remote-mode).
